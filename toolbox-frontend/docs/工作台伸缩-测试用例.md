## 1. 被测逻辑概述

工作台网格为 `grid-cols-4 gap-4 auto-rows-[180px]`，尺寸映射三档：`s=1×1`、`m=2×1`、`l=2×2`。

另有**超宽档 `xl=4×1`**，只对内容会横向变多的工具开放（Base64 / JSON / 哈希）：

- 只加宽不加高（行数仍为 1），因此不存在"拉宽后右侧一片空白"的问题；
- Base64 / JSON：切换/复制收进左侧竖栏，输入与结果左右各半并排；
- 哈希：三种算法各占一整行，SHA-512 的 128 字符约 920px，4 列宽（约 1100px 可用）可完整显示。

时间戳 / 密码 / UUID 不开放 `xl`：实测拉到 4 列后内容墨迹只占 25%~63% 宽度，多出来的都是空白。

伸缩链路：

1. `onHandlePointerDown` 记录指针起点、当前跨度与实测格宽（由网格容器宽度反算，不写死）。
2. `onHandlePointerMove` 把指针位移换算成期望跨度 `spansFromDelta`，再按该工具的 `availableSizes` 吸附成可用档位 `snapSize`，写入 `previewSize` 实时预览。
3. `pointerUp` 时若档位有变化，调用 `onResize(path, size)` → `useDashboardWidgets.setSize` 校验白名单并落盘。

关键常量与阈值：

- `SNAP_EASING = 0.6`：换算跨度时把 `(格宽+GAP)` 缩小到 60%，翻档阈值 ≈ `0.5 × 0.6 × (格宽+GAP)`。1440 视口下格宽 272px，横向阈值约 86px（优化前 144px），纵向约 59px（优化前 98px）。
- 列数上限从固定 2 放开为 `GRID_COLS`（4）：只有声明了 `xl` 的工具才会真的吸附到 4 列，其余工具拖再远也只到 `m`。
- `snapSize` 平局规则：距离相同时取更宽的一档，但**仅限行数相符**——否则拖到 3 列（m 与 xl 等距）要多拖一整格才有反馈，而 s 档向下拖又会被莫名推到 l。
- 手柄热区 40×40px，视觉斜纹 12×12px。

## 4. 已知限制

1. Hash 的 s 档只计算当前选中算法，不铺开三种；列表视图在 l / xl 档。
2. jsdom 缺少 `setPointerCapture`，组件内使用可选链调用，测试无需额外打桩。
3. jsdom 无 Web Crypto，`SizeVariants.test.jsx` 在测试内注入了确定性替身，仅用于验证"出结果"，不校验真实摘要。
4. 测试环境未加载完整 i18n 资源，部分断言按 DOM 位置或英文 key 定位，避免与语言包耦合。
5. `xl` 档只在 4 列网格下有意义；窄视口（< 1024）沿用既有横向滚动行为（与档位无关，`m` 档同样如此）。
6. `snapSize` 的平局偏向更宽档只在行数相符时生效，测试对两条分支都有断言，改动时勿只改一侧。
